# Topic 7 — Operating Systems

> 🏢 **Why it matters:** OS is a **core CS-fundamentals** section in nearly every BD trainee paper (Cefalo, TigerIT, Enosis, BJIT). Expect 4–8 MCQs on process/thread, scheduling, deadlock, memory, and synchronization.

## Process vs Thread (top OS question)

**Process** = a program in execution with its **own memory space**. **Thread** = a lightweight unit *inside* a process that **shares** the process's memory.

| | Process | Thread |
|---|---------|--------|
| Memory | Own private | Shared within process |
| Creation | Heavy | Light |
| Communication | IPC (pipes, sockets) | Shared memory (easy) |
| Crash | Isolated | Can crash whole process |

🧠 **Process = private memory; Thread = shared memory.** Threads → faster but need synchronization (race conditions).

## Process states

```
NEW → READY ⇄ RUNNING → TERMINATED
         ↑        ↓
       WAITING ◀──┘ (I/O; returns to READY, not RUNNING)
```

## CPU Scheduling algorithms

| Algorithm | Idea | Note |
|-----------|------|------|
| **FCFS** | first come first served | simple; convoy effect |
| **SJF** | shortest job first | best avg wait; starvation risk |
| **Round Robin** | fixed time quantum, rotate | fair; interactive; preemptive |
| **Priority** | highest priority first | starvation (fix: aging) |

🧠 **Round Robin = preemptive + fair (time slices). SJF = optimal avg waiting time.** Preemptive = OS can interrupt (RR, SRTF); non-preemptive = runs to completion (FCFS, basic SJF).

## Deadlock (guaranteed question)

Four conditions — **all must hold** (Coffman):
1. **Mutual exclusion** 2. **Hold and wait** 3. **No preemption** 4. **Circular wait**

Break any one to prevent. Handling: prevention, avoidance (**Banker's algorithm**), detection & recovery.

🧠 **Deadlock (stuck forever in a cycle) ≠ Starvation (keeps getting skipped).**

## Synchronization

- **Race condition**: outcome depends on thread timing on shared data.
- **Critical section**: code accessing shared resource — must be mutually exclusive.
- **Mutex**: lock, one thread at a time, owned. **Semaphore**: counter allowing up to N; binary semaphore ≈ mutex but not owned.

## Memory management

- **Virtual memory**: each process gets a private address space; disk used as overflow (**swap**).
- **Paging**: fixed-size **pages** ↔ **frames**; a **page fault** = accessing a page not in RAM. Constant faulting = **thrashing**.
- **Segmentation**: variable-size logical segments (code/stack/heap).
- **Fragmentation**: **Internal** (wasted space inside allocated block — paging) vs **External** (gaps between blocks — segmentation).

## Other high-frequency facts

- **Kernel** = privileged core; **user space** = restricted apps; cross via **system calls**.
- **Zombie** = child finished, not reaped by parent. **Orphan** = parent died, child adopted by init (PID 1).
- **Context switch** = save one process's state, load another's — pure overhead.
- **Belady's anomaly**: more frames can cause more page faults (FIFO page replacement).
- Page replacement: **FIFO, LRU, Optimal**. LRU = replace least recently used.

## Common mistakes & tricks

- ❌ "Threads have separate memory" → they **share** it.
- ❌ "Round Robin is non-preemptive" → it's **preemptive**.
- ❌ "Paging causes external fragmentation" → **internal**; segmentation → external.
- ❌ "Deadlock needs any one condition" → needs **all four**.
- 🧠 **SJF = best average waiting time. RR = fairness.**

## 📄 Cheat sheet
```
Process=own memory | Thread=shared memory (needs sync)
States: New→Ready→Running→(Waiting)→Terminated
Scheduling: FCFS(convoy) | SJF(best avg wait, starvation) | RR(preemptive,fair) | Priority(aging)
Deadlock 4 conds: mutual exclusion, hold&wait, no preemption, circular wait (ALL)
Mutex=1 owned | Semaphore=N counter | Race condition on shared data
Virtual memory+paging(pages↔frames), page fault, thrashing
Fragmentation: internal(paging) vs external(segmentation)
Zombie=child dead unreaped | Orphan=parent dead (init adopts)
Page replacement: FIFO/LRU/Optimal; Belady's anomaly (FIFO)
```
